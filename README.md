# Aster — AI Personal Assistant

Aster is a multi-user AI personal assistant built with Next.js. It connects to your apps (Gmail, WhatsApp), summarizes your day into an AI-generated brief, delivers scheduled briefings, and lets you chat with an agent that can pull live data from your connected accounts.

## Features

- **Landing page** — marketing site with hero, features, integrations, how-it-works, and FAQ sections.
- **Authentication** — email/password, Google OAuth, and phone OTP sign-in (SMS via messages.dev), backed by [InsForge](https://insforge.dev) auth. Multi-user by design; no shared tokens.
- **Dashboard** — "Today's Brief" generated by an AI model from all connected providers, plus stat cards, an activity chart, priority items, and connected-apps overview. Provider data is normalized through a pluggable registry (`lib/server/dashboard/`), with refresh rate-limiting.
- **Gmail integration** — first-party Google OAuth flow (per-user tokens stored server-side), REST endpoints for emails/labels/send, and an MCP endpoint exposing Gmail tools with an in-app tool runner.
- **WhatsApp integration** — [Baileys](https://github.com/WhiskeySockets/Baileys) socket with a pairing-code flow (no QR scanning required), DB-backed auth state and message store, status/reconnect/disconnect endpoints, and an MCP endpoint exposing WhatsApp tools.
- **Agent chat ("Aster")** — streaming chat (NDJSON over an OpenAI-compatible Chat Completions API) with a bounded tool loop that calls namespaced Gmail/WhatsApp MCP tools, live status events, follow-up suggestions, and DB-persisted conversations (1-day validity).
- **Briefings** — user-defined scheduled briefings. A single Trigger.dev cron (every 15 minutes) asks the app to atomically claim due runs, then enqueues one generation job per run. Briefing detail pages with categorized items, history, compose, and send.
- **Alerts, Pricing, Settings** pages.

## Getting started

1. **Install dependencies**

   ```bash
   npm install
   ```

2. **Configure environment** — create `.env.local`:

   ```bash
   # InsForge (auth + database)
   NEXT_PUBLIC_INSFORGE_BASE_URL=...
   NEXT_PUBLIC_INSFORGE_ANON_KEY=...
   INSFORGE_ADMIN_API_KEY=...        # phone auth user management

   # AI (any OpenAI-compatible endpoint)
   OPENAI_API_KEY=...
   OPENAI_MODEL=gpt-4o-mini          # optional, default gpt-4o-mini
   OPENAI_BASE_URL=...               # optional, e.g. Gemini's OpenAI-compatible URL

   # Gmail integration (Google Cloud OAuth client)
   GOOGLE_CLIENT_ID=...
   GOOGLE_CLIENT_SECRET=...

   # Phone OTP sign-in (messages.dev)
   MESSAGES_DEV_API_KEY=...
   MESSAGES_DEV_FROM=...
   MESSAGES_DEV_BASE_URL=...         # optional
   PHONE_AUTH_SECRET=...             # random secret for signing OTP state

   # Internal job endpoints (shared with Trigger.dev)
   INTERNAL_API_SECRET=...
   ```

3. **Run the dev server**

   ```bash
   npm run dev
   ```

   Open [http://localhost:3000](http://localhost:3000).

## Background jobs (Trigger.dev)

Scheduled briefings run through Trigger.dev (`trigger.config.ts`):

```bash
npm run trigger:dev      # run tasks locally against your dev server
npm run trigger:deploy   # deploy tasks
```

Set these in the Trigger.dev dashboard environment:

- `APP_BASE_URL` — public URL of the deployed app
- `INTERNAL_API_SECRET` — must match the app's value; jobs authenticate to `/api/briefings/claim-due` and `/api/briefings/run` with the `x-internal-secret` header

The scheduler is intentionally thin: one cron tick every 15 minutes claims due briefing runs atomically in the database, then fans out one `briefing-generate` job per run (idempotent per `runId`).

## Deployment notes

- **WhatsApp requires a persistent Node.js process.** The Baileys socket lives in a `globalThis` map, so serverless platforms that freeze/recycle processes will drop the connection. Deploy to a long-running Node host (or a single always-on instance) for reliable WhatsApp connectivity.
- MCP endpoints (`/api/integrations/{gmail,whatsapp}/mcp`) are consumed by the in-app agent; tools are namespaced per provider.
